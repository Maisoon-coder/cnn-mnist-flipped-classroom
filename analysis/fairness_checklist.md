**结论先说**：**七项对比条件全部同口径，FC 与 CNN 的差异可以归因到"结构"这一项；但只有单种子，不能声称"CNN 一定更准"。**

## 一、逐项核对

| # | 条件 | FC 与 CNN 是否相同 | 证据（可复查） | 判定 |
|---|---|---|---|---|
| 1 | 数据 | 相同 | 同一份 `MNIST(train=True)` 60000 张 / `test=False` 10000 张；`get_loaders()` 只实例化一次数据集对象，三类加载器共享 | 通过 |
| 2 | 预处理 | 相同 | 两模型都走 `data.build_transform()`：ToTensor + Normalize(0.1307, 0.3081)，无增强 | 通过 |
| 3 | 轮次 / batch / 优化器 / 学习率 | 相同 | `config.json` 只有一个 `train` 块，没有按模型覆盖：epochs=5、batch=64、adam、lr=1e-3、weight_decay=0 | 通过 |
| 4 | 随机种子 | 相同 | `seed: 42`；打乱用独立 `torch.Generator`（`make_generator`），不依赖模型初始化消耗的随机数，避免两模型看到的样本顺序分叉 | 通过 |
| 5 | 损失与输出口径 | 相同 | 两模型都输出 `[N,10]` logits，统一 `nn.CrossEntropyLoss`；没有额外 Softmax | 通过 |

| 8 | 轮次选择 | 未按测试集挑轮 | `select_last_epoch: true`，两模型都取第 5 轮；FC 第 4 轮更高（97.47%）仍未被选中 | 通过 |

## 二、三条需要注意的边界（写进结论页，别当结论用）

1. **单种子（seed=42）**：无法区分"结构差异"和"这一次初始化的运气"。
   acc 差 1.81 个百分点是**这次运行**的观测值，不是总体期望。三种子实验是扩展项，本次未做。

2. **耗时不可跨机器比较**：`train_seconds` 是 8 线程 CPU 上的墙钟时间，
   FC 185.0 s / CNN 220.8 s。它能说明"本机同条件下 CNN 反而慢 19%"，**不能**推出"CNN 普遍更慢"，
   也不能与其他同学的 GPU 数字混用。

3. **环境与组员 3 的核对不是同一台机**：组员 3 的 H2b 记录为 py3.12.15 / torch 2.11.0+cu128 / RTX 5070，
   与本包 `environment.txt`（CPU）不同。两者得出一致的 97.19% / 99.00%，是**跨环境可复现**的旁证；
   但正式结果以本包的 CPU 环境为准，PPT 上不要写"在 GPU 上训练"。

## 四、给组员 4 的一条确认请求

（`torch.set_num_threads(8)`）与是否关闭了 MKLDNN。这两项会影响墙钟时间。
如果只是"默认值恰好是 8 线程"，请在 README 写明；否则第 10 页讲耗时时容易被追问口径。
（不影响准确率，只影响耗时那半句话。）
