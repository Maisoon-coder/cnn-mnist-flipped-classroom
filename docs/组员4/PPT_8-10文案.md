## 第 8 页｜结构如何落实为代码（50 秒）

**一句话结论**：方案里那张表，逐行对应到 `nn.Conv2d` / `nn.MaxPool2d` / `nn.Linear` 三类层；**尺寸在代码里能一路算出来**。

**页面元素**

- **左（占 60%）**：`figures/fig10_network.png` —— 七段结构 + 每段形状 + 每段参数量
- **右（占 40%）**：`src/models.py` 的 `CNNNet` 片段，只保留 6 行关键代码（高亮 `padding=2`、`16*5*5`、三层 Linear）

```python
self.conv1 = nn.Conv2d(1, 6, 5, padding=2)   # 1→6 通道，5×5 核
self.conv2 = nn.Conv2d(6, 16, 5)            # 6→16 通道
self.pool  = nn.MaxPool2d(2, 2)
self.fc1 = nn.Linear(16 * 5 * 5, 120)       # 400 → 120
self.fc2 = nn.Linear(120, 84)
self.fc3 = nn.Linear(84, 10)                # 输出 10 个 logits
```

**口播（50 秒）**

> 这张图是从输入到输出的完整路径，下面三行代码就是它的实现。
> 输入是 1×28×28 的灰度图。第一层卷积用 5×5 的核、补两圈零，所以输出还是 28×28——**padding=2 就是为了不丢掉边缘像素**。
> 过一次 2×2 池化，尺寸减半到 14×14；第二层卷积不补零，14 减 5 加 1 等于 10；再池化一次就到 5×5。
> 所以展平之后是 **16 乘以 5 乘以 5 等于 400 维**——这个数字算错，后面全连接会直接报维度错误。
> 分类头是 400→120→84→10。整个网络一共 **6.17 万参数**，而同样是两层全连接的基线是 **20.35 万**。

**可能被追问**

| 问题 | 答案 |
|---|---|
| 400 是怎么来的？ | 第二个池化输出 16×5×5，`torch.flatten` 后是 16×5×5 = 400 |
| `padding=2` 有什么用？ | 5×5 核滑过 28×28 会缩到 24×24；补两圈零后 `28+4−5+1 = 28`，尺寸不变、边缘也参与运算 |
| 为什么是两层卷积不是一层？ | 一层只能看局部笔画的组合；两层让感受野从 5 扩到 14，才够认出整个数字（组员 2 会讲感受野推导） |
| 为什么输出不套 Softmax？ | `nn.CrossEntropyLoss` 内部已含 log_softmax，再套一次等于算两遍，loss 会偏 |

## 第 9 页｜参数是怎么学出来的（40 秒）

**一句话结论**：训练就是**五步循环**——清梯度、前向、算损失、反向、更新；一个 epoch 走 938 批。

**页面元素**

- **上半**：`figures/fig11_training_loop.png`（五步 + 对应代码 + 循环箭头）
- **下半或右下**：一行实测数字

| 项 | 值 |
|---|---:|
| 训练样本 / batch | 60000 / 64 |
| 一个 epoch 的批数 | **938**（末尾 32 张也保留，不丢） |
| 轮数 | 5 |
| 5 轮累计耗时 | FC **185 s** / CNN **221 s**（CPU，8 线程） |

**口播（40 秒）**

> 训练循环就五步。
> 第一步清空上一次的梯度——**PyTorch 的梯度是累加的，不清零就会叠加上一批的梯度**，这是最常见的 bug。
> 第二步前向，第三步算交叉熵损失，第四步反向传播求梯度，第五步优化器按梯度改参数。
> **注意 backward 只算梯度不改参数，step 才真正改权重**，这两步不是一回事。
> 六万张图、每批 64 张，就是一个 epoch 938 批；跑 5 轮。CNN 5 轮累计约 221 秒。

**可能被追问**

| 问题 | 答案 |
|---|---|
| 为什么要 `zero_grad()`？ | `.grad` 是累加的，不清零会把这批和上批的梯度加起来，更新方向就错了 |
| `backward()` 和 `step()` 的区别？ | 前者只计算梯度，后者按梯度更新参数 |
| `model.eval()` 和 `torch.no_grad()` 是一回事吗？ | 不是。前者切换 Dropout/BatchNorm 的行为，后者关闭梯度记录；评估时两个一起用 |
| 为什么 batch 是 64？ | 256 张一批梯度更稳但更新次数少；64 是速度与稳定性的折中，两个模型用同一个值保证可比 |

## 第 10 页｜能不能做单图预测（60 秒，含现场演示）

**一句话结论**：权重保存下来之后，读图 → 同一套预处理 → 前向 → 取最大概率，**单张图约 1 秒出结果**。

**页面元素**

- **左**：`figures/fig12_predict_demo.png`（输入图 + 10 类概率条形图，预测 7，99.98%）
- **右**：现场终端或备用视频（二选一，同一段时间）
- **底部**：一行提醒——「单张图说明程序可运行；整体效果由 10000 张测试集评价」

**现场命令**

```bash
python -m src.predict --checkpoint outputs/main_seed42_v1/checkpoints/cnn_seed42_last.pt \
                     --image demo/digit7_test0.png
```

**口播（60 秒）**

> 前面讲的都是训练，这页演示推理。
> 权重已经训练好并保存了，现场只做三件事：读一张 28×28 的灰度图、用**和训练完全相同的预处理**把它变成张量、送进网络。
> 网络输出 10 个分数，取最大的那个就是预测结果。这张测试集第 0 张的图，模型给出的 7 的概率是 **99.98%**。
> 这里要强调一点：**单张图只能说明程序能跑通，不能说明模型好不好**——整体效果由 10000 张测试集的 99.00% 来评价。
> 另外提示一下，MNIST 是白字黑底，如果你拿白纸黑字的照片来测，要先反色，否则会识别错。

**可能被追问**

| 问题 | 答案 |
|---|---|
| 为什么现场不训练？ | 五轮只要几分钟，但现场训练会引入不可控风险（环境、时间），演示目的是"程序可用"，训练证据在前面的日志里 |
| 99.98% 是"模型很有把握"吗？ | 不是。`softmax` 的输出是打分，未做校准，不能当置信度解读；说"模型给了 99.98 分"即可 |
| 为什么不用自己手写的字演示？ | 手写照片与训练分布（居中、白字黑底、28×28）差异大，容易误判。要用需先反色、居中、缩放；作为附加展示可以，但要说明 |
| 权重保存和重新训练有什么区别？ | 权重只存参数，不存优化器状态和轮次记录；所以必须配 `config.json` 和 `seed/epoch` 元信息才能追溯 |
