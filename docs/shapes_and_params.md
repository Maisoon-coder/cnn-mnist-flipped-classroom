## 一、全连接基线（FC）

结构：`Flatten → Linear(784→256) → ReLU → Linear(256→10)`

| 层 | 输入 → 输出（省略 batch 维） | 参数量计算 | 参数量 |
|---|---|---|---:|
| Flatten | 1×28×28 → 784 | 无参数 | 0 |
| Linear1 + ReLU | 784 → 256 | 784×256 + 256（偏置） | 200,960 |
| Linear2（输出 logits） | 256 → 10 | 256×10 + 10（偏置） | 2,570 |
| **合计** | | | **203,530** |

## 二、简易 CNN（LeNet 风格）

| 层 | 关键设置 | 输出（省略 batch 维） | 尺寸计算 | 参数量计算 | 参数量 |
|---|---|---|---|---:|---:|
| 输入 | 灰度图 | 1×28×28 | — | — | 0 |
| Conv1 + ReLU | 1→6，5×5，stride=1，**padding=2** | 6×28×28 | (28+2×2−5)/1+1 = 28 | (5×5×1+1)×6 | 156 |
| Pool1 | 最大池化 2×2，stride=2 | 6×14×14 | (28−2)/2+1 = 14 | 无参数 | 0 |
| Conv2 + ReLU | 6→16，5×5，stride=1，**padding=0** | 16×10×10 | (14−5)/1+1 = 10 | (5×5×6+1)×16 | 2,416 |
| Pool2 | 最大池化 2×2，stride=2 | 16×5×5 | (10−2)/2+1 = 5 | 无参数 | 0 |
| Flatten | — | **400** | 16×5×5 | 无参数 | 0 |
| FC1 + ReLU | 400→120 | 120 | — | (400+1)×120 | 48,120 |
| FC2 + ReLU | 120→84 | 84 | — | (120+1)×84 | 10,164 |
| FC3（输出 logits） | 84→10 | 10 | — | (84+1)×10 | 850 |
| **合计** | | | | | **61,706** |

尺寸公式（dilation=1）：`H_out = floor((H_in + 2×padding − kernel) / stride) + 1`

## 三、参数对比（第 7 页可直接用）

| 项目 | FC | CNN | 差异 |
|---|---:|---:|---|
| 总参数量（含偏置） | 203,530 | 61,706 | CNN 少 141,824 |
| 相对比例 | 100% | 30.32% | CNN 减少 **69.68%** |
| 倍数关系 | 3.30 倍 | 1.00 倍 | FC 约为 CNN 的 3.30 倍 |

口径提示：以上是**整网**可训练参数（含偏置）的结构计算值，不能拿单个卷积层的 156 个参数去和整个 FC 的 203,530 直接对比——两者不是同一口径。

## 五、讲第 7 页时的三个关键点

1. **400 是怎么来的**：16 通道 × 5 × 5 = 400。这是最容易算错、也最容易被追问的一步。
   padding=2 让 Conv1 输出仍是 28×28；若写成 padding=0，第一次池化后就只剩 12×12，整条链路全变。
2. **第二次池化后是 16×5×5**，所以分类头输入是 400，不是 256、也不是 784。
3. **CNN 参数更少但更深**：它把参数花在"6 个 5×5 的检测器"上，而不是给 784 个像素位置各配一套权重。

## 六、留给组员 2 复核的三处口径

- 卷积参数量只与 `(k×k×C_in+1)×C_out` 有关，**不随图像空间位置数增加**——这正是权值共享的体现。
- 池化层参数量为 0，但**参与反向传播**（最大池化把梯度回传给前向取到最大值的位置）。
