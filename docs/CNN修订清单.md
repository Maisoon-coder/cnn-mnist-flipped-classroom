## 二、P0 修订项

### R-01 「CNN 两大优势」补齐为独立论点

**落笔位置**
- 总体方案 §3.3（讲解深度表）、§八（第 7 页与第 11 页之间）
- 分工细则 §2.5（组员 2 汇报要点）、§6.6（组员 5 汇报要点）

**现状**
原任务第三条硬性要求是"CNN 相比全连接网络的两大优势"，需作为完整论点讲出。当前方案把它拆散在三处：§3.3 表内分为"局部连接／权值共享／通道"三个技术点；第 2 页只讲 FC 局限；第 7 页只讲参数量。**没有任何一页或一句话把"两大优势"成对说出来。**

**问题**
10 分钟结束后，听众能记住"卷积怎么算""参数变少"，但缺少一句固定的结论句。对照评分表时，这一条容易被判为"未讲到"。§3.4「统一讲解口径」在主动弱化该论点，只做了"留条件"，没做"下结论"。

**修订内容**
在第 7 页（结构页）右下角增设固定结论框，或单独占第 11 页上半：

```text
CNN 相对全连接网络的两大优势
① 参数效率
   局部连接：每个输出只连接输入的一小块
   权值共享：同一个核在整幅图的所有位置复用同一套权重
   → 203,530 → 61,706，参数减少 69.68%，仅为 FC 的 30.3%
② 空间结构利用
   保留二维邻接关系，不做无约束的全连接展开
   逐层抽象：边缘 → 笔画 → 数字轮廓
   池化带来有限的局部平移鲁棒性
   → 相同训练条件下测试准确率提升 【实测】 个百分点

口径：以上为本次固定配置下的观察结果；卷积是平移等变的，池化只增加有限的
局部平移鲁棒性；CNN 不保证在任何设置下都更优，也不保证训练一定更快。
```

**原则**：结论说满，口径留条件。§3.4 保持原文，它在管"不许断言"，不负责"给出结论"。

**验收**：第 7 或第 11 页存在该框；讲解人在 30 秒内能完整说出两条优势；§3.3 表不再承担"讲论点"的职责。

### R-03 环境与权重的版本锁定

**落笔位置**：总体方案 §2.3、§5.2（保存加载检查）；分工细则 §5.2（4-01）、§5.6

**现状**
§2.2 要求"记录版本"，§2.3 说"不在未验证时填入版本号"，但没有规定何时锁死、用什么方式加载权重。

**问题**
PyTorch 2.6 起 `torch.load` 默认 `weights_only=True`，加载包含非张量内容的 checkpoint 会直接报错。现场演示机器与开发机器若版本不同，最坏情况是开场加载失败。

**修订内容**
1. §2.3 增补：`requirements.txt` 在 D4 首次完整跑通后**立即锁死精确版本**（`torch==x.y.z`、`torchvision==x.y.z`、`numpy==x.y.z`），此后不得随意升级。
2. §5.2 「保存加载」检查行补充加载写法约定：

```python
state = torch.load(ckpt_path, map_location="cpu", weights_only=False)
```

3. 分工细则 §5.2 的 4-01 交付物明确为：`requirements.txt`（锁版本）+ `environment.txt`（Python/PyTorch/torchvision 版本、device 型号、是否有 CUDA）。
4. §5.6 答疑准备增加一条：「权重跨版本加载可能失败，为什么？我们怎么防？」答案指向 `map_location` + 锁版本。

**验收**：在新环境（或新的虚拟环境）中按 README 安装依赖后，两个权重均能加载并复现评估结果。

### R-04 训练轮次的决策规则

**落笔位置**：总体方案 §2.1（末段）、§2.2（epochs 行）、§5.3

**现状**
§2.1「训练 5 轮」、§2.2「epochs = 5」均为硬编码，且不划验证集、取最后一轮。逻辑上严谨（不拿测试集挑模型），但没有处理一种现实情况。

**问题**
若 5 轮后曲线仍未平、双方都停在 96% 左右，对比的说服力会明显下降。§5.3 只写了"若 CNN 未优于 FC 先排查实现错误"，缺"两边都欠拟合"的退路。

**修订内容**
§2.1 末段改为「轮次在冒烟测试后一次性确定」：

```text
正式训练前（D5）用同一配置各跑 5 轮，据结果锁定轮次：
· 末两轮测试准确率提升均小于 0.3 个百分点，且双方均不低于 97% → 锁定 epochs=5；
· 曲线仍在明显上升，或任一方低于 97% → 双方一并改为 epochs=10，创建新 run_id
  （如 main_seed42_v2），旧日志保留不覆盖。
该决策只做一次；正式训练开始后不再调整。正式结果仍取最后一轮，
不按测试集准确率挑选轮次，测试集不参与任何选择。
```

§2.2「epochs」行改为「5（默认，按 §2.1 规则确定后冻结）」。

**验收**：`config.json` 中的 epochs 与实际训练轮次一致；若改过轮次，`outputs/` 下同时存在旧 run_id 的记录与说明。
