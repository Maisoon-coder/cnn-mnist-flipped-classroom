## 一、任务定位与最终成果

### 1.1 核心问题

围绕一个问题组织全部工作：**为什么 CNN 比普通全连接网络更适合利用图像的局部空间结构？这种设计在 MNIST 上体现出怎样的效果与参数量差异？**

讲解与实验形成以下闭环：

```text
图像具有二维结构、相邻像素相关
    ↓
普通全连接层没有显式利用局部性与空间权值共享
    ↓
卷积通过局部连接、权值共享提取特征，池化缩小空间尺寸
    ↓
搭建简易 CNN，与 FC 使用同一套数据和训练评估流程
    ↓
用准确率、参数量、学习曲线、特征响应及错误样本支撑分析
    ↓
说明本次实验的结论、适用条件与局限
```

完成后，听众应能理解一次卷积如何计算、感受野如何变化、池化的作用、模型如何训练，以及本组对比实验是否公平。

## 二、数据方案与实验约定

### 2.1 数据处理

使用 MNIST 官方训练集 60,000 张、测试集 10,000 张；单图为 28×28 灰度图，标签为 0—9。

处理顺序：读取图像 → 转为灰度张量并缩放到 0—1 → 按 mean=0.1307、std=0.3081 标准化 → 组成 batch。

| 项目 | 统一约定 | 需要检查 |
|---|---|---|
| 模型输入 | 浮点张量 `[N,1,28,28]` | 通道维不能遗漏 |
| 标签 | 整数张量 `[N]`，取值 0—9 | 使用分类损失所需的整数类型 |
| 训练数据加载 | 打乱顺序，保留末尾不足一个 batch 的数据 | 两模型用相同数据顺序种子 |
| 测试数据加载 | 不打乱，不更新参数 | 便于追踪错误样本索引 |
| 标准化 | 两模型共用相同预处理 | 预测时也必须使用同一套参数 |
| 数据存储 | 项目相对路径下的数据目录 | 不硬编码个人电脑路径 |

基础方案不划验证集：正式训练前固定全部设置，训练 5 轮，使用最后一轮作为报告结果。每轮测试指标仅用于满足作业的曲线展示，不用于挑模型、选种子或决定训练何时停止。

若团队决定调参，必须在调参之前启用验证集方案：例如从官方训练集固定划出 55,000 张训练、5,000 张验证，保留划分种子或索引；所有模型用相同划分，仅用验证集作选择。变更后在 PPT 和 README 写明实际样本数，不能继续声称使用全部 60,000 张训练。

### 2.2 主实验配置

| 配置项 | 建议固定值 | 说明 |
|---|---|---|
| 模型 | `fc`、`cnn` | 唯一主要比较变量 |
| seed | 42 | 每次训练前重置各随机源 |
| batch size | 64 | 两模型一致 |
| epochs | 5 | 预先固定；不以测试曲线决定加轮次 |
| 优化器 | Adam | 两模型一致，记录其他实际使用参数 |
| 学习率 | 0.001 | 两模型一致 |
| 损失 | 交叉熵 | 输入 logits 和整数标签 |
| weight decay | 0 | 基础版本不额外加入正则化变量 |
| 数据加载进程数 | 0 起步 | 先减少环境与随机性问题 |
| 设备 | 同一台机器上的同一设备 | CPU 或 GPU 均可，记录型号 |
| 权重选择 | 最后一轮 | 不从测试准确率最高的轮次挑选 |

正式训练前保存一份配置快照；两模型使用相同的数据划分与数据打乱机制。模型初始化会消耗不同数量的随机数，因此数据打乱最好使用独立、明确的随机生成器，不仅依赖一次全局设种子。

记录 Python、PyTorch、torchvision、NumPy 等实际版本；设置 Python、NumPy、PyTorch 的随机种子，并在可行时启用确定性计算。可复现指在记录的条件下可重新得到相符结果，不承诺跨硬件或跨版本逐位相同。

## 三、模型结构与原理讲解方案

### 3.1 FC 基线

结构：`Flatten → Linear(784,256) → ReLU → Linear(256,10)`。

| 层 | 输出（省略 batch 维） | 参数量 |
|---|---|---:|
| 输入与 Flatten | 784 | 0 |
| Linear(784→256) + ReLU | 256 | 200,960 |
| Linear(256→10) | 10 个 logits | 2,570 |
| 合计 | | **203,530** |

保留这个基线是为了对比网络结构，不故意给它减少训练轮次、使用不同预处理或更差的学习率。

### 3.2 简易 CNN

采用资料中的 LeNet 风格结构，但在材料中写出具体配置，避免让听众误以为它与某个历史版本完全一致。

| 层 | 关键设置 | 输出（省略 batch 维） | 参数量 |
|---|---|---|---:|
| 输入 | 灰度图 | 1×28×28 | 0 |
| Conv1 + ReLU | 1→6，5×5，stride=1，padding=2 | 6×28×28 | 156 |
| Pool1 | 最大池化，2×2，stride=2 | 6×14×14 | 0 |
| Conv2 + ReLU | 6→16，5×5，stride=1，padding=0 | 16×10×10 | 2,416 |
| Pool2 | 最大池化，2×2，stride=2 | 16×5×5 | 0 |
| Flatten | 16×5×5 | 400 | 0 |
| FC1 + ReLU | 400→120 | 120 | 48,120 |
| FC2 + ReLU | 120→84 | 84 | 10,164 |
| FC3 | 84→10 | 10 个 logits | 850 |
| 合计 | | | **61,706** |

参数核算：卷积层为 `(核高×核宽×输入通道+1)×输出通道`；全连接层为 `(输入维数+1)×输出维数`，这里均包含偏置。

本设计中 CNN 比 FC 少 **141,824** 个参数，减少约 **69.68%**，FC 参数量约为 CNN 的 **3.30 倍**。这些是结构计算值，仍需用最终代码统计核对；不能把某个卷积层的参数与整个 FC 网络的参数混为同一口径。

### 3.3 原理必须讲到的深度

| 概念 | 讲解方式 | 听众应能回答 |
|---|---|---|
| 卷积计算 | 用 3×3 小窗口手算一次乘加，再展示滑动 | 一个输出值如何产生？ |
| 局部连接 | 在图上圈出一个输出对应的输入局部 | 为什么不用连接全部像素？ |
| 权值共享 | 展示同一个核在不同位置复用 | 为什么同一笔画出现在不同位置可以使用同一检测规则？ |
| 通道 | 从一张输入到多张输出特征图 | 卷积核数量与输出通道有什么关系？ |
| 感受野 | 逐层叠加观察区域 | 深一层的单个特征能看到多大范围？ |
| ReLU | 显示负值置零的小例子 | 为什么连续线性变换之间需要非线性？ |
| 池化 | 对同一个 2×2 窗口算最大值与平均值 | 二者区别、空间降采样和参数情况是什么？ |
| 分类输出 | 10 个 logits、预测类别与交叉熵关系 | 为什么训练前不重复 Softmax？ |

感受野可用 `r_new = r_old + (k−1)×j_old`、`j_new = j_old×stride` 递推，其中 r 为理论感受野边长，j 为相邻输出在原图上的间距；从 r=1、j=1 开始，本 CNN 依次得到：

| 位置 | 理论感受野边长 r | 输入上的间距 j |
|---|---:|---:|
| Conv1 后 | 5 | 1 |
| Pool1 后 | 6 | 2 |
| Conv2 后 | 14 | 2 |
| Pool2 后 | 16 | 4 |

这是单个特征位置的理论范围，边缘位置还会受到 padding 影响；后续全连接分类头再汇总多个空间位置的信息。

### 3.4 统一讲解口径

- Flatten 保留像素值和固定顺序；普通全连接层缺少的是显式的二维局部性及空间权值共享，不能说图像变成了“无序数字”。
- 在适当条件下，卷积具有平移等变性；池化可能增加有限的局部平移鲁棒性。不能说整个网络对任何平移都严格不变。
- 池化层没有可学习参数，但参与梯度传播；它降低空间分辨率，可能减少后续计算或全连接参数，并非自动保证不过拟合。
- 参数更少不意味着训练必然更快；CNN 也不保证在任何设置下都比 FC 更准确。
- 两层 3×3 比一层 5×5 参数更少的判断需要通道数等条件；“18 对 25”仅适用于单通道且不计偏置的简化例子。
- 第一层卷积核可以用笔画或方向响应帮助理解，但不能强行给每个核命名，也不能仅凭特征图证明网络理解了数字语义。

### 4.2 模块职责与交接接口

| 模块 | 负责内容 | 对外约定 |
|---|---|---|
| data.py | 数据集、转换、数据加载器和随机打乱 | 提供训练加载器、训练评估加载器、测试加载器；预处理一致 |

### 4.3 日志约定

`metrics.csv`：每个模型、每轮、每个评估数据划分各一行。

| 字段 | 含义与口径 |
|---|---|
| run_id / model / seed | 实验编号、fc 或 cnn、种子 |
| epoch / split | 轮次；train 或 test，启用验证方案时增加 val |
| n_samples | 该次评估实际处理的样本数 |
| loss | 全部样本的平均交叉熵 |
| accuracy | 正确数除以总样本数，内部保存为 0—1 |
| train_seconds | 可选；该轮训练耗时，不包含额外评估和作图 |

loss 应按样本数加权累计，不能简单平均不同大小 batch 的均值。accuracy 同样以总正确数和总样本数计算，避免末尾 batch 影响口径。

`results.csv`：每模型一行，至少包含实验编号、模型、种子、报告轮次、测试准确率、测试 loss、总参数量和权重相对路径。`errors_*.csv` 至少包含测试集索引、真实标签、预测标签；可附预测类别概率，勿将该概率解释为经过校准的可靠程度。

图表与 PPT 展示百分数，日志保留 0—1 数值。比如日志 0.98 应显示为 98%，避免出现 0.98% 的格式错误。

## 五、训练、验证与结果解释

### 5.1 训练流程

1. 读取配置，设置随机源，创建输出目录，保存环境和配置快照。
2. 创建数据加载器和选定模型，将模型与 batch 放在相同设备。
3. 每轮设置训练模式；每个 batch 依次清空梯度、前向、计算交叉熵、反向、更新参数。
4. 每轮结束切换评估模式并关闭梯度记录，对训练集与测试集进行统一评估。
5. 写入日志，核对样本数；下一轮训练前恢复训练模式。
6. 保存最后一轮模型；在新建模型实例上加载并重新评估，核对预测结果。

训练侧正式曲线使用轮末评估值；若额外记录训练期间 batch loss，用不同字段标明，不能把两种统计过程混为一条曲线。

### 5.2 正式实验之前的检查

| 检查 | 方法 | 通过标准 |
|---|---|---|
| 输入与标签 | 查看一个真实 batch | 输入、标签形状与取值符合约定 |
| 两模型前向 | 分别送入同一 batch | 输出 `[N,10]`，无维度错误 |
| 参数量 | 用程序统计可训练参数 | 与 203,530 / 61,706 对应 |
| 单步训练 | 完成一次前向、损失、反向与更新 | 损失为有限数，参数发生更新 |
| 评估流程 | 对固定小样本运行 | 不产生参数更新，统计样本数正确 |
| 保存加载 | 在新实例中加载同一权重 | 相同环境下相同输入的预测一致 |

这些检查服务于发现实际错误，不要求为本作业搭建复杂测试框架。通过后再开始完整训练。

准确率差应写成“百分点”，参数下降写成相对比例。需要时补充错误率的相对变化，但必须说明分母，避免把 1 个百分点说成“准确率提高 1 倍”。

若资源允许，将 seed=42、43、44 各训练一对模型，总计 6 次训练；已有可复用的 seed=42 正式运行无需重复。展示三个种子的全部结果、均值与标准差，不只展示最好一次。该扩展用于观察随机波动，不能单靠三次实验宣称普遍显著优势。

若 CNN 没有优于 FC，先排查尺寸、预处理、loss 用法、评估模式和训练是否完整；修复实现错误后按相同规则重跑双方，并记录原因。如果实现正确仍未出现优势，就报告当前设置的真实结果与局限。

## 六、三类可视化的制作规范

### 6.1 学习曲线

建议生成一张 2×2 面板图：训练 loss、测试 loss、训练 accuracy、测试 accuracy；每个面板叠加 FC 与 CNN 两条曲线。横轴为 epoch，颜色始终对应同一模型，图例、单位、实验编号清楚。

解读顺序：是否学习 → 收敛是否稳定 → 训练和测试是否存在差距 → 两模型差别是否值得强调。不要仅凭一轮小波动断定过拟合；若截取准确率坐标轴，要清楚标出范围，避免夸大微小差异。

### 6.2 卷积核与中间特征图

- 卷积核图：展示 Conv1 的 6 个 5×5 核，标明层名和通道，使用合理且一致的色标说明权重正负。
- 特征图：固定一张测试图片，展示原图、Conv1 激活后特征、部分 Conv2 激活后特征；保留样本索引和通道编号。
- 图中注明截取位置是卷积后、ReLU 后还是池化后，避免尺寸和解释不一致。
- 展示前将张量从计算图中分离并移至 CPU。若为突出纹理逐张归一化，图注写明“各图独立缩放，不用于比较绝对响应强弱”。
- 卷积核是学到的权重，特征图是具体图片经过网络后的响应，这一区别必须讲清。

### 6.3 错误样本

分别保存 FC 和 CNN 的误判清单。输出各模型前 12 个错误索引对应的样本网格，数量不足时展示全部；如无错误，明确记录，不拼造样本。

每张图至少标注“真实：x / 预测：y”。PPT 可从完整网格中选 2—4 张有代表性的图，说明这是用于解释的示例；不能用精选示例替代全测试集的定量结果。

分析可从笔画相近、书写异常、笔画粘连或图像偏移等角度提出解释，并注明这些是观察性判断。可选地展示“两个模型都错、仅 FC 错、仅 CNN 错”的同样本对照，增强分析的公平性。

## 七、单图预测与现场演示

### 7.1 预测流程

选择来源清楚的测试图片 → 按统一流程处理 → 加载 CNN 最终权重 → 切换评估模式并关闭梯度记录 → 输出 logits → 取最大值类别 → 显示图片与预测结果。

优先使用与训练分布一致的单个数字图片。自写图片作为附加展示时，检查灰度、黑白背景极性、数字裁剪、等比例缩放和居中；这类图片的处理必须说明，并避免为某一张图片反复调整模型。

### 7.2 60 秒演示脚本

| 时间 | 动作 | 讲解要点 |
|---|---|---|
| 0—10 秒 | 展示图片与权重位置 | 已提前完成训练，现场执行推理 |
| 10—25 秒 | 运行单图预测入口 | 同一预处理，将图片转为 `[1,1,28,28]` |
| 25—40 秒 | 显示类别与原图/处理后图 | 10 个输出对应数字 0—9 |
| 40—50 秒 | 可选显示另一张图或概率 | 概率只用于说明模型输出 |
| 50—60 秒 | 收束并转结果页 | 单图展示说明程序可用，整体效果由完整测试集评价 |

现场运行与备用视频二选一，占用同一段时间，不连续播放两遍。若遇路径或环境故障，直接切换已验证的视频；成员分工文档中指定操作者与切换负责人。
